# 管理本文と画像の preview

Bot 所有者は `/preview` に定義 TOML、実行 Guild の state JSON、`image1`〜`image8` の個別画像を添付して、管理本文を実行場所で確認できます。DM では実行できません。[コマンド登録手順](discord-role-management.md#テスト-guild-へのコマンド登録)で既存コマンドとともにテスト Guild に登録します。

[サンプル定義](examples/discord-message-preview.toml)は `guide.png` 一件を3投稿で共有します。新しいテスト Guild で対応表がない場合は、以下の `guild_id` を実行先の実 ID に置き換えた JSON を明示的に添付します。既存の管理状態がある場合はその Guild 用の最新 state を使います。

```json
{"schema_version":1,"guild_id":"実行GuildのID","roles":{},"channels":{}}
```

`message_sets.<群ID>.body` と `threads.<ThreadID>.body` の各要素が一投稿です。`id` と `body` は必須で、同じ配列内の ID は重複できません。画像参照は `![代替テキスト](添付名)` または `![代替テキスト](attachment://添付名)` を独立した行に書きます。ファイル名は空白・括弧・パス区切りを含めず、同名の画像を添付してください。外部画像 URL は取得しません。コードブロック・インラインコード・インデントされたコードの例示は展開しません。

連続した画像行は最大10項目ずつ Media Gallery にまとめます。本文と画像の順序、本文配列の順序を保持し、同じ画像は各投稿に一度だけ添付します。画像は群と補足本文を合わせて入力全体で最大8件、PNG・JPEG・GIF・WebP に対応します。重複添付名、画像不足・形式不一致、空白だけの本文を入力エラーにします。

描画後の Text Display は一投稿で合計4000文字、全コンポーネントは40件、画像の代替テキストは1024文字以内です。添付上限は Interaction の `attachment_size_limit` に従います。一投稿の画像合計は24 MiBまでとし、Discord の25 MiB request 上限に対して残り1 MiBを JSON・multipart ヘッダー用に確保します。定義と state は各1 MiBまでの UTF-8 です。投稿単位の超過は Message 論理 ID とともに診断し、本文を暗黙分割しません。

添付の取得前に ephemeral defer を返し、最初の投稿は original response を明示編集、追加投稿は個別に ephemeral followup を送信します。補足本文には最初に「補足：スレッド名」を表示します。本文のメンション表記は維持し、すべての表示・診断に `allowed_mentions` を明示して通知を抑制します。入力 state と実物の Channel・Thread・管理投稿は変更しません。

受領応答は Interaction 作成から3秒、取得・描画・返却は10分以内を処理予算とします。rate limit 待機と SDK 内部の再試行もタイムアウトで止め、診断返却には続く2分を確保します。返却失敗時は確認済みの投稿数と残りの先頭 ID を表示します。応答消失が起きた投稿は返却済みか不明な場合があり、診断自体が送れない場合は Bot のエラーとして記録されます。

管理投稿の作成・編集、論理リンクの解決・未作成注記は後続 Issue #16・#19 で追加する範囲です。この段階では本文中の論理リンクをそのまま保持します。

## テスト Guild での確認

1. 開発用 Bot とテスト Guild に `/preview` を登録し、サンプル・同じ Guild の state・`guide.png` を添付します。
2. 本文→画像→本文、2件目の群本文、補足本文の順に実行者だけが見えることを確認します。他のメンバーには表示されません。
3. 同じ画像が3投稿で見え、補足 Thread や管理投稿が実際には作成されないことを確認します。
4. テスト用 User・Role のメンションと `@everyone` を本文に書き、表記が維持され通知が発生しないことを確認します。
5. 実行前後の管理投稿と手元の最新 state が変わっていないことを確認します。
6. 添付不足・重複名・4000文字超過の本文で診断が表示されることを確認します。所有者以外と DM からは実行できません。

自動テストは描画の公開操作、返却順・失敗停止・期限、および Discord builder の payload を検証します。実表示と端末の通知設定は上記の実環境確認が必要です。
