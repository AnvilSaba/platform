# ホワイトリストをDB更新番号でキャッシュする

public-apiはアクセス時にPostgreSQLのホワイトリスト更新番号を確認し、キャッシュと同じ番号なら再利用し、異なれば一覧を取得してJSONを再生成する。現行の変更時ファイル生成でも通常時の鮮度は保てているが、プロセス分離後のファイル共有・転送を避け、アクセスごとの全件取得とJSON生成も減らすため、この方式を選ぶ。公開パス`/whitelist.json`とJSON形式は維持する。

一覧に影響するDB変更をトリガーで検知し、同じトランザクションで更新番号を加算する。更新日時やランダムトークンより実装が単純で、変更の進行を追いやすい更新番号を使う。キャッシュ生成時は一覧と更新番号を同じDBスナップショットから取得し、アプリごとにキャッシュを保持する。

アクセスごとの軽いDB問い合わせは残る。DBの更新番号確認または再生成に失敗した場合は、最後の成功結果を配信し続ける方式ではなく503を返す。したがって、一覧の提供可否はDBの稼働に依存する。
