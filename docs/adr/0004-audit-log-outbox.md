# 監査ログを分離したoutbox経由でBotから送信する

監査ログ本体を配送状態から分離してDBに保存し、監査ログのINSERTトリガーでログIDを参照するoutboxを作成する。業務データの変更、監査ログ、outboxは同じトランザクションで保存し、いずれかの保存に失敗した場合は全体をロールバックする。複数アプリからの記録で送信予定の作成漏れを防ぐためであり、配送をアプリ内の一時的な処理だけで済ませる方式よりDB処理が増える。

ログには発生時点のイベントの事実、発生日時、操作主体と対象を保存し、自動処理の主体も区別する。表示用の文章・装飾と送信先はBotが送信時に決め、記録側とoutboxは送信先を持たない。監査対象は現行どおりとし、管理者コマンドのブロック・解除は今回追加しない。ephemeral応答はその場で返し、outboxによる後日の応答は行わない。

Botはoutboxから配送し、成功後にoutboxを削除する。監査ログ本体は残し、今回は自動削除を導入しない。Discordへの投稿成功からoutbox削除までに停止すると重複送信が起こり得るが、欠落を防ぐため、まれな重複を許容する。表示には発生日時とイベントIDを含める。

一時的な送信失敗は間隔を延ばして再試行し、送信先削除・権限不足は要対応としてoutboxに残して自動再試行を止める。管理者コマンドで対象IDまたは停止中の全件を再試行待ちに戻せるようにする。失敗したログがあっても後続を進めるため、到着順と発生順は一致するとは限らない。

送信先は必須設定とし、不正な送信先は通常の失敗処理で扱う。送信役は1つを前提とし、複数Bot向けの処理権やリースは設けない。
